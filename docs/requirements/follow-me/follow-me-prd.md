## 1. 背景与目标

### 1.1 背景
团队拥有实体 Cozmo 与 Mac mini，底层用开源库 pycozmo 替代官方 App。pycozmo 只提供硬件控制（电机、摄像头流、自带动画播放、音频、LED、方块 LED 与加速度计、传感器），**不提供**人脸/人体检测、视觉方块识别、TTS 等高层智能，这些需在 Mac 端自建。

### 1.2 要解决的问题
让 Cozmo 从"只能被底层驱动"升级为"能识别人并跟随、带情绪表达、断网也能动"的可运行系统，并在此过程中验证三层架构（感知/任务/认知）与本地认知层（Gemma 4）的可行性。

### 1.3 本次目标
- 打通 Mac↔Cozmo 链路，能播放自带动画。
- 搭建三层架构，使 Cozmo 在无认知模型时也能自主活动并与方块互动。
- 实现基于 MediaPipe Pose 的跟人走，跟随中表达心情；人丢失时按阶梯产生情绪变化（疑惑→焦急）并搜索。
- 接入本地认知层，由其决定意图与心情，并提供规则反射兜底。

### 1.4 非目标（Out of Scope）
- 不做 TTS / 语音说话（Cozmo 本阶段不出声，心情靠表情/动画/自带音效）。
- 不做视觉方块定位（方块靠无线电交互，非视觉）。
- 不做精确测距、地图构建、自动充电对接、人脸身份识别、通用物体识别。
- 不做带数值衰减的情绪模型（仅固定预设心情）。
- 不接入云端认知模型（保留为后续可切换 provider）。

## 3. 用户故事（User Stories）

> 角色约定：「演示者」= 启动并操作系统的人；「被跟随者」= 站在 Cozmo 前被识别跟随的人。多数情况下为同一人。
> **识别口径**：系统只做 MediaPipe Pose 全身检测，**不认脸、不辨身份**，仅判断"画面里有没有人"，不区分是不是同一个人。「看着我/找我」均指"画面中是否有人"。
> **表情 vs 动画**：本文「表情」指程序化表情参数（眼睛开合/眉等，可实时连续控制），「动画」指自带 `.bin` 动画资源（整段播放）。每种心情用哪类机制见第 4 节。
> 所有"心情→动画/LED"的具体映射见第 4 节心情集合。

### 步骤一：建立连接

**US1 — 连接并播放自带动画**（P0）
作为演示者，我希望启动后应用能连上 Cozmo 并播放一段自带表情/动作动画，以便确认 Mac↔Cozmo 链路打通。
- Given 已完成 Cozmo 唤醒并使 Mac 连上其 Wi‑Fi
- When 运行 `main.py --demo connect`
- Then 数秒内 Cozmo 播放一段可见的自带表情/动作动画
- And 控制台打印"连接成功"与当前电池电压

**US2 — 安全断开**（P1）
作为演示者，我希望程序退出时能安全断开与 Cozmo 的连接，以便不留下异常状态。
- Given 程序正在运行且已连接 Cozmo
- When 演示者正常退出程序
- Then Cozmo 停止当前动作并断开连接，无残留电机运转

### 步骤二：自由活动 + 找方块

**US3 — 自主随机移动**（P0）
作为演示者，我希望 Cozmo 连上后能自行随机活动（前进/转向），以便无人工干预也能"动起来"。
- Given Cozmo 已连接且处于自由活动状态
- When 无其他更高优先级目标
- Then Cozmo 以随机方式前进/转向移动
- And 期间按规则/随机进入一种预设心情（默认在 calm/happy/playful/curious 中按权重选取），并播放对应表达

**US4 — 悬崖/碰撞安全反射**（P0）
作为演示者，我希望 Cozmo 在任意状态下检测到悬崖或碰撞时立即停止并后退，以便避免跌落或卡死。
- Given Cozmo 正在移动（任意状态）
- When 检测到悬崖或碰撞
- Then Cozmo 立即停止并后退，且该反射不被任何上层目标或认知层覆盖

**US5 — 连接方块并进入玩方块**（P1）
作为演示者，我希望 Cozmo 在自由活动中已连接方块时可转入"玩方块"，以便与方块互动。
- Given Cozmo 处于自由活动状态且方块已通过无线电连接
- When 满足以下任一进入条件：方块上报被拍/被移动事件，或自由活动持续达到 `T_seek_cube`（默认 10s）仍未发生更高优先级目标
- Then Cozmo 切换到玩方块状态并点亮方块 LED
- And 方块 LED 的颜色/节奏随当前心情变化

**US6 — 方块互动触发心情与动画**（P0）
作为演示者，我希望方块被拍或被移动时 Cozmo 快速做出情绪反应，以便体现互动感。
- Given Cozmo 处于玩方块状态
- When 方块加速度计上报"被拍"（tapped）或"被移动"（moved）
- Then Cozmo 在 1s 内切到对应心情动画并改变方块 LED：`tapped → happy`，`moved → playful`

**US7 — 无互动后回到自由活动**（P2）
作为演示者，我希望玩方块一段时间无互动后 Cozmo 自动回到自由活动，以便不长期停滞。
- Given Cozmo 处于玩方块状态
- When 在 `T_cube_idle`（默认 15s）内无任何方块互动
- Then Cozmo 回到自由活动状态

### 步骤三：跟人走

**US8 — 检测到人并跟随转向**（P0）
作为被跟随者，我希望我在 Cozmo 前方左右移动时它能转向保持朝向我，以便它"看着我"。
- Given Cozmo 处于跟随状态且画面中检测到人
- When 人体水平位置偏出中心死区 `center_deadzone`（默认 ±0.15，归一化）的某一侧
- Then Cozmo 朝该侧转向；当人回到死区内则停止转向（死区入配置，避免抖动）

**US9 — 按远近前进/后退**（P0）
作为被跟随者，我希望我靠近或远离时 Cozmo 有相应的前进/后退反应，以便维持跟随距离。
- Given Cozmo 处于跟随状态且检测到人
- When 人体在画面中变小（变远）或变大（变近）
- Then 变远时 Cozmo 前进，变近时 Cozmo 停止或后退，使人体尺寸维持在目标区间 `size_target`（默认 [0.30, 0.45]，归一化）内
- And 验收以方向序列判定（不要求精确距离）：被跟随者从约 1.5m 走到约 0.5m，Cozmo 表现为"先前进 → 进入目标区间停止 → 继续靠近则后退"

**US10 — 跟随中表达心情**（P1）
作为被跟随者，我希望 Cozmo 跟随时持续表达匹配的心情，以便感受到它有情绪。
- Given Cozmo 处于跟随状态
- When 稳定跟随
- Then Cozmo 表现为 calm 心情；当靠近或重新找到人时切换为 happy 并播放对应动画
- And 移动过程中持续播放与当前心情匹配的动画

**US11 — 丢人后的情绪阶梯与搜索**（P0）
作为被跟随者，我希望我离开画面后 Cozmo 先疑惑再焦急地找我，回来后开心，以便表现出"在乎我在不在"。
- Given Cozmo 处于跟随状态
- When 连续 `N_lost`（默认 5 帧）未检出人，`person.visible` 置 false，**以该时刻为 T1/T2 计时起点**
- And When 计时超过 T1（🔶【待确认 Q1】默认 2s），Then Cozmo 进入搜索状态，表现为 confused（疑惑），左右张望/原地慢转扫描
- And When 计时超过 T2（🔶【待确认 Q1】默认 5s），Then Cozmo 升级为 anxious（焦急），加快/扩大扫描
- And When 重新检测到人（关键情绪事件），Then 立即切到 happy 并回到跟随状态，**不受心情防抖最短保持时间约束**（见 US13）
- 备注：构想中"超长未找到 → 放弃回 FREE_ROAM"分支本阶段不实现，搜索持续进行直到复见或人为停止。

### 贯穿能力：可观测性

**US12 — 实时查看黑板状态**（P1）
作为演示者，我希望能实时查看黑板（世界状态）字段，以便联调与验收。
> 说明：本故事对应 Q5。Q5 默认建议"需要"，故 US12 在默认下即纳入本阶段（P1）；若 Q5 被推翻为"不需要"，则降级为可选。
- Given 系统运行中
- When 演示者查看调试面板或日志
- Then 能实时观察黑板关键字段（电池、是否看见人/方块、当前心情/意图、关键事件）的更新

### 贯穿能力：心情系统

**US13 — 心情防抖（最短保持时间）**（P1）
作为被跟随者，我希望 Cozmo 的心情不会频繁抖动切换，以便观感稳定。
- Given Cozmo 处于某一心情
- When 在最短保持时间 `T_mood_hold`（🔶【待确认 Q6】默认 1.0s，所有心情统一，入配置）内出现新的**普通**心情指令
- Then Cozmo 保持当前心情直到 `T_mood_hold` 结束再切换，避免动画被频繁打断
- And 例外：**关键情绪事件**（复见人触发 happy、丢人升级到 confused/anxious、安全反射）可立即打断防抖，不等待 `T_mood_hold`
- 可测验收：在 `T_mood_hold` 内连续下发两次不同的普通 mood，动画不被第二次打断；下发关键情绪事件则立即切换。

### 贯穿能力：认知层（本地 Gemma 4）

**US14 — 认知层决定意图与心情**（P0）
作为演示者，我希望本地认知层能基于世界状态摘要决定下一步意图与心情并下发，以便机器人行为由"认知"驱动。
- Given 三层架构运行，认知层可达
- When 认知层按事件驱动或低频轮询读取世界状态摘要
- Then 认知层输出结构化的 `intention` 与 `mood` 下发任务层，由任务层执行
- And 认知层不直接发送电机指令（只改目标与心情）
- 可测验收：调试日志中认知层相邻两次调用间隔 ≥ `cog_min_interval`（默认 1.0s），单位时间调用次数远低于感知帧率（~30Hz）

**US15 — 认知层超时/不可达时的规则兜底**（P0）
作为演示者，我希望认知层慢、超时或不可达时机器人仍按规则照常运行，以便系统具备健壮性。
- Given 认知层未在 `cog_timeout`（默认 2.0s，入配置）内返回，或不可达
- When 任务层需要意图/心情
- Then 任务层**不阻塞**，立即由确定性规则给出默认意图与心情（例：看见人→跟随；人丢→T1 疑惑/T2 焦急；低电量→停）并继续执行
- And When 认知层稍后返回，Then 其结果可覆盖规则给出的意图/心情，但不可覆盖安全反射

## 4. 心情集合（产品定义）

第一阶段采用 6 种固定预设心情，不做数值衰减。每种心情映射到一组表达；机制分两类——「表情」= 程序化表情参数（眼/眉，实时连续），「动画」= 自带 `.bin` 资源（整段播放）；具体动画 `.bin` 名在实现时选定并配置。

| 心情 | 触发场景（产品语义） | 表达方向 | 主要机制 |
|---|---|---|---|
| `calm` 平静 | 默认/待机、稳定跟随 | 待机表情、呼吸式眨眼 | 表情 |
| `happy` 开心 | 找到人/方块、互动成功、重新找到人 | 开心/兴奋表达 + 绿色 LED | 动画 + LED |
| `playful` 顽皮 | 自由活动玩方块 | 顽皮表达、点亮方块 LED | 动画 + LED |
| `curious` 好奇 | 发现新目标、扫描中 | 头部转动 + 好奇表情 | 表情 + 动作 |
| `confused` 疑惑 | 人短暂消失（> T1） | 搜寻表达、左右张望 | 动画 + 动作 |
| `anxious` 焦急 | 人长时间消失（> T2） | 急促表情 + 黄/红 LED + 加快搜索 | 表情 + LED + 动作 |

## 5. 非功能性需求

- **响应性**：方块互动触发心情动画的响应时间 ≤ 1s；丢人情绪阶梯按 T1/T2 阈值触发。
- **健壮性**：认知层超时/不可达时由规则兜底维持运行（US15）；pycozmo 连接异常时自动重连，重连期间不崩溃；超过重试上限 `reconnect_max_retries`（默认 3 次）才安全退出（停电机、断连接）。
- **安全性**：悬崖/碰撞安全反射在感知层闭环、立即生效，优先级最高，不可被上层或认知层覆盖（US4）。
- **检测稳定性**：人体检测做多帧确认与平滑；连续 `N_lost`（默认 5 帧）未检出才置 `person.visible=false`（亦为 T1/T2 计时起点），减少抖动与误丢失。
- **离线运行**：认知层本地化，系统不依赖外网即可完整运行。
- **可配置性**：以下阈值统一通过配置文件调整。🔶【待确认 Q1/Q6/Q7】下表默认值为初值，做成配置项，以真机联调为准微调：

| 配置项 | 默认值 | 含义 |
|---|---|---|
| `T1` / `T2` | 2s / 5s | 丢人→疑惑 / →焦急 |
| `N_lost` | 5 帧 | 连续未检出帧数，置 visible=false 与 T1/T2 起点 |
| `center_deadzone` | ±0.15 | 转向中心死区（归一化） |
| `size_target` | [0.30, 0.45] | 跟随人体尺寸目标区间（归一化） |
| `T_mood_hold` | 1.0s | 心情防抖最短保持时间 |
| `T_seek_cube` | 10s | 自由活动多久后可转入玩方块 |
| `T_cube_idle` | 15s | 玩方块无互动超时回自由活动 |
| `cog_min_interval` | 1.0s | 认知层最小调用间隔 |
| `cog_timeout` | 2.0s | 认知层超时阈值 |
| `reconnect_max_retries` | 3 | 连接重试上限 |

  此外动画名、心情映射、认知模型选型亦通过配置文件调整。

## 6. 指标与成功标准

按里程碑验收，每一步独立产出可运行 demo。

| 里程碑 | 成功标准 | 对应 US |
|---|---|---|
| M1 连接 | `--demo connect` 播放动画并打印电量 | US1、US2 |

## 7. 风险与依赖

- **单目测距不精确**：跟随距离只能近似（靠尺寸区间控制），可能抖动；US9 验收以"有正确方向的前进/后退反应"为准，不要求精确距离。
- **摄像头分辨率/帧率低**：MediaPipe Pose 在低质画面上可能漏检，依赖多帧平滑（见非功能性需求）。
- **本地模型资源占用**：认知模型与感知、pycozmo 同台共存，需关注内存峰值与首字延迟。
- **认知工具链成熟度**：本地 Gemma 4 的 JSON 约束/多模态能力需在 M4 实测验证。
- **pycozmo 稳定性**：官方自述开发中，依赖重连与异常恢复机制。
- **具体动画名未定**：各场景/心情的自带动画 `.bin` 名需实现时选定并配置（关联 Q4）。
