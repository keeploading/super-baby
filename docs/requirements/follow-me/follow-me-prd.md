## 1. 概述

### 1.1 背景
Cozmo 原厂 App 已停止维护，需用开源底层引擎 pycozmo 重建控制链路。pycozmo 只提供底层硬件控制（电机、摄像头、表情、动画、音频、LED、传感器），不提供人脸/人体识别、视觉物体识别、地图、TTS 等高层智能，这些能力需在 Mac 端自建。

本阶段目标是**跑通三层智能体架构**，让 Cozmo 能：识别人并跟随、带情绪表达、在丢失目标时产生情绪变化（疑惑 → 焦急），并具备无 LLM 也能自主活动的兜底能力。

### 1.2 目标（Goals）
- **G1**：打通 Mac ↔ Cozmo 链路，能播放自带表情/动作动画。
- **G2**：搭建三层架构（感知 / 任务 / 认知）+ 心情系统，实现自由活动与通过无线电"找方块/玩方块"。
- **G3**：用 MediaPipe Pose 实现人体识别与跟随，带心情表达，丢人后情绪升级并搜索。
- **G4**：第一阶段即接入本地认知层（Gemma 4，Ollama），决定意图与心情，并提供规则反射兜底。

### 1.3 非目标（Non-Goals，本阶段不做）
- 不做 TTS / 语音说话（留作后续增强）。
- 不做视觉方块/标记识别与精确测距（方块靠无线电交互，距离靠尺寸近似）。
- 不做带数值衰减的情绪模型（本阶段为固定预设心情）。
- 不做地图构建、自动充电对接。
- 不做云端模型部署（接口预留可切换，但默认本地）。

## 2. 术语表

| 术语 | 含义 |
|---|---|
| HAL | 硬件抽象层，封装 pycozmo 的薄抽象（电机/表情/声音/LED/方块/连接） |
| 三层架构 | Gat 1998 三层模型：感知层(Reactive) / 任务层(Sequencer) / 认知层(Deliberator) |
| 黑板 / Belief store | 层间唯一共享状态（World/Belief），通过它解耦各层 |
| 反射兜底 | 在认知模型慢/超时/不可达时给出默认意图与心情的确定性规则 |
| 安全反射 | 悬崖/碰撞等在感知层本层闭环、立即响应、不可被上层覆盖的保护行为 |
| MediaPipe Pose | Google 的人体骨架检测，运行在 Mac 端用于实时跟随 |
| 视觉伺服 | 通过"保持目标在画面中央 + 维持尺寸区间"做跟随控制，而非精确测距 |
| T1 / T2 | 丢人阈值：T1 进入疑惑、T2 升级焦急 |

## 3. 技术前提与约束

### 3.1 pycozmo 能力边界
- ✅ **提供**：车轮/头部/举升电机、摄像头图像流、程序化表情（眼睛开合/表情参数）、`.bin` 动画播放、WAV 音频播放（22kHz/16bit/单声道）、背包 LED、方块 LED 与方块加速度计、悬崖/加速度/陀螺仪/电池电压传感器。
- ❌ **未实现（需 Mac 端自建）**：人脸/人体检测、视觉方块/标记识别、物体识别、地图构建、TTS、自动充电对接。
- ⚠️ **待验证（不得当作确定前提，见 SPIKE-1/SPIKE-2）**：
  - **完整 `.bin` 动画回放**的稳定性（pycozmo 对官方动画资源的回放支持可能不完整）。若不稳定，心情表达降级为"程序化表情 + LED + 自带音效"（见 FR-1.2 / SPIKE-1）。
  - **摄像头实测参数**：分辨率约 320×240 灰度、帧率约 15fps 且可能抖动/丢帧，均为待实测值；Cozmo 视角极低（贴地仰视），MediaPipe 常只能看到人体下半身（见 SPIKE-2）。这些是设计假设，需在 M3 前实测（见 11.4 待实测参数）。

### 3.2 关键设计取舍
- **C1 找方块不靠视觉**：方块通过无线电与机器人通信。"找方块/玩方块" = 随机移动 + 点亮方块 LED + 读方块加速度计（被拍/被移动）交互。
- **C2 人体识别在 Mac 端**：摄像头帧传到 Mac，用 MediaPipe Pose 检测骨架，估计水平位置与远近（躯干/肩宽或包围盒高度近似）。
- **C3 单目近似测距**：Cozmo 单摄像头，跟随采用视觉伺服而非精确测距。

### 3.3 网络约束
- **C4 本地模型、无需外网**：认知层默认本地 LLM（Mac mini 运行），不依赖外网，Wi-Fi 可一直连着 Cozmo，无需第二网卡。
- 连 Cozmo 的 Wi-Fi（PSK）会占用 Mac 无线网卡，连着时上不了外网；因本地化不受影响。
- **C5 模型与依赖须预先下载缓存**：模型首次下载/更新及 Python 依赖安装需要外网，而连 Cozmo 时上不了外网。因此部署时须在连接 Cozmo 之前完成模型与依赖的本地缓存，运行期不依赖外网。
- 仅当将来切换**云端模型**时才需第二条网络（USB-以太网/第二网卡）。无论本地或云端，对"认知模型暂时不可达/超时"都有反射兜底。

### 3.4 验证性需求（Spike，前置于对应里程碑）
以下为"必须先验证、再据结果定方案"的需求；每个 Spike 有明确产出与判定条件。

| 编号 | 验证内容 | 产出与判定 | 前置于 | 关联 |
|---|---|---|---|---|
| SPIKE-1 | pycozmo 能否稳定回放至少一段官方 `.bin` 动画 | 产出：可回放则记录可用动画清单；否则采用"程序化表情+LED+音效"方案。判定：连续 10 次回放无崩溃/无明显卡顿即视为稳定 | M1 | R1 |
| SPIKE-2 | Cozmo 实拍画面下 MediaPipe Pose 的人体检出率 | 录制典型跟随场景视频，统计逐帧"至少检出 1 个有效关键点"的帧占比与抖动；产出实测分辨率/帧率/检出率。判定：检出率达到 visible 帧门限要求（见 FR-3.2）所需的最低水平，否则调整门限或检测策略 | M3 | R2、R19（最高风险） |
| SPIKE-3 | 本地 LLM 选型与工具链验证 | 在 32GB Mac mini 实测候选本地模型（Gemma 系列优先）的：可加载性、内存峰值、首字延迟、结构化 JSON 输出/function calling 支持度。判定：选定满足 NFR-2 轮询周期与 NFR-4 资源约束的型号 | M4 | R4 |
| SPIKE-4 | 感知端到端节拍与控制延迟预算 | 实测"摄像头帧经 Wi-Fi 图传 → MediaPipe → 写黑板"的端到端帧率与延迟，确认是否能达到感知 ~30Hz 或需下调目标节拍 | M3 | R20、NFR-2 |

> 说明：SPIKE 是需求而非任务排期。其结果可能反过来修改 FR-1.2 的表达方式、FR-3.1/3.2 的门限、FR-4.1 的型号、NFR-2 的节拍目标——这些项当前均按"待验证假设"处理。

## 4. 系统架构需求

### 4.1 三层架构（ARCH）
核心原则：**每层不同周期，LLM 永不进实时控制环**；下层向上报"事实"，上层向下发"目标"，通过共享黑板解耦。

| 层 | 角色 | 周期 | 职责 |
|---|---|---|---|
| 认知层 Deliberator | LLM agent loop | ～秒级 / 事件驱动 | 读 Belief 摘要，决定 Intention(目标)与 Mood(心情)下发；规则反射兜底 |
| 任务层 Sequencer | 状态机/行为 | ～10Hz | 用 FSM 执行目标（free_roam / play_cube / follow / search），向 HAL 下指令，把心情落到动画与行为强度 |
| 感知层 Reactive | 实时 | ～30Hz / 回调 | 摄像头帧→MediaPipe Pose、方块加速度计、电池、姿态；安全反射本层闭环；把事实写入黑板 |

- **ARCH-1**：三层必须各自独立周期运行，不得相互阻塞。
- **ARCH-2**：层间通信只能通过黑板，禁止跨层直接调用绕过黑板。
- **ARCH-3**：HAL 必须隔离上层与 pycozmo，支持 mock 以便测试。
- **ARCH-5（并发模型）**：必须显式定义并发隔离，使任一耗时操作不阻塞其他层节拍：
  - pycozmo 自带事件循环、MediaPipe 推理、LLM 推理均为"重/阻塞"操作，须与感知/任务节拍隔离（独立线程、进程或 asyncio 任务，具体由架构设计选型）。
  - **硬约束**：MediaPipe 推理不得阻塞感知层向黑板写其他事实（传感器/电池/姿态）；LLM 推理不得阻塞感知层或任务层节拍（认知层独立线程或子进程）。
  - 验收：在 LLM 单次推理耗时 ≥2s 的情况下，任务层节拍抖动不超过其周期的 20%，感知层安全反射响应不受影响。
- **ARCH-6（黑板并发安全与写者归属）**：每个黑板字段有且仅有一个写者层，其余层只读；读取以"一致快照"为单位（一次读取看到的字段相互一致）。
  - `timestamp / battery_voltage / pose / cliff_detected / person / cube`：**仅感知层写**。
  - `mood / intention`：**仅认知层写**（例外见 ARCH-7 与 MOOD-1）。
  - 任务层对上述字段**只读**。
  - `person.visible` 与 `person.last_seen_ts` 须**原子一起更新**，不得出现 visible=true 但 last_seen_ts 过期之类的撕裂状态。

### 4.2 黑板字段（World / Belief store）
- **ARCH-4**：黑板为层间唯一共享状态，至少包含下列字段：

```
world = {
  "timestamp": float,
  "battery_voltage": float,
  "pose": {"x", "y", "angle"},
  "cliff_detected": bool,
  "person": {
     "visible": bool,
     "cx_norm": float,        # 人体中心水平归一化位置 [-1,1]
     "size_norm": float,      # 包围盒/肩宽归一化，近似远近
     "last_seen_ts": float,
  },
  "cube": {
     "connected": bool,
     "tapped": bool,          # 来自加速度计
     "moved": bool,
  },
  "mood": "calm|happy|playful|curious|confused|anxious",
  "intention": "free_roam|play_cube|follow_person|search_person|...",
}
```

### 4.3 决策优先级仲裁（ARCH-7）
当多个来源同时试图影响行为/心情时，按下列优先级裁决，高优先级覆盖低优先级；过期决策（时间戳早于当前一致快照）一律丢弃。

| 优先级 | 来源 | 说明 | 可否被上层覆盖 |
|---|---|---|---|
| 1（最高） | 安全反射（悬崖/低电量保护） | 感知层本层闭环，立即生效 | **否**，任何层不可覆盖 |
| 2 | 任务层丢人计时驱动的 mood/状态（T1→confused，T2→anxious） | 确定性、低延迟，不依赖 LLM | 否（认知层不得把"丢人焦急"改回 calm，除非人已复现） |
| 3 | 认知层下发的 intention/mood | LLM 决策，秒级 | 是（被 1、2 覆盖） |
| 4（最低） | 规则反射兜底 | 认知层不可达/超时时的默认值 | 是（认知层返回后即覆盖） |

- **冲突解决**：同一时刻只采纳当前最高优先级来源的结果；安全反射触发时，所有运动目标让位于安全行为。
- **过期丢弃**：认知层返回的决策若其输入快照已过期（如基于"看见人"决策但黑板已变为"人丢失超过 T2"），任务层丢弃该决策，按当前事实执行。

### 4.4 丢人计时归属（ARCH-8）
- 丢人计时（T1/T2）及由此触发的状态升级（FOLLOW→SEARCH→焦急）**归属任务层**，理由：确定性、低延迟、不依赖 LLM 可用性。
- 认知层可在此基础上叠加表达（如附加理由、辅助选择搜索策略），但不得决定 T1/T2 是否触发。
- 全文以本条为准；MOOD-1、FR-3.6/3.7、FR-4.9 的措辞均统一为"丢人计时与升级由任务层驱动"。

### 4.5 mood 与 intention 合法组合（ARCH-9）
- mood 与 intention 不是任意自由组合；任务层在关键状态转移时**可直接设派生 mood**，以保证一致性，无需等认知层。
- 约束举例（非穷举）：`intention=search_person` 时 mood 只能为 `confused` 或 `anxious`；`intention=follow_person` 且稳定跟随时默认 `calm`，刚复现人时 `happy`；不得出现 `intention=follow_person` 同时 `mood=anxious`。
- 当认知层下发的组合违反约束时，任务层以"当前状态的派生 mood"为准（属 ARCH-7 优先级 2 的延伸）。

## 5. 心情系统需求

第一阶段采用**有限的预设心情**，每种映射到自带 `.bin` 动画 + 表情 + 背包 LED，**不做数值衰减**。

| 心情 mood | 触发场景 | 表达（具体动画名待实现时确认） |
|---|---|---|
| `calm` 平静 | 默认/待机、稳定跟随 | 轻微待机表情、呼吸式眨眼 |
| `happy` 开心 | 找到人/方块、互动成功 | happy/excited 动画 + 绿色 LED |
| `playful` 顽皮 | 自由活动玩方块 | playful 动画、点亮方块 LED |
| `curious` 好奇 | 发现新目标、扫描中 | 头部转动 + 好奇表情 |
| `confused` 疑惑 | 人短暂消失（>T1） | confused/搜寻动画、左右张望 |
| `anxious` 焦急 | 人长时间消失（>T2） | 急促表情 + 黄/红 LED + 加快搜索 |

- **MOOD-1**：心情默认由认知层决定并写入黑板，任务层翻译成具体动画与行为强度；**但丢人计时驱动的 mood（T1→confused、T2→anxious）由任务层直接设定（见 ARCH-8），优先级高于认知层（见 ARCH-7）**。
- **MOOD-2**：心情切换须有最短保持时间（防抖，默认 `mood_min_hold = 1s`，可配置），避免动画频繁打断。**例外**：安全反射、丢人 T1/T2 升级、人复现等"关键事件"可立即打断防抖（防抖只约束普通心情切换，不约束关键事件，见 FR-2.4 / AC 时延口径）。
- **MOOD-3**：默认阈值 `T1 = 2s`（人消失→疑惑），`T2 = 5s`（持续消失→焦急），须可在 `config.yaml` 配置（阈值合理性见 11.3 待用户确认）。计时起点为 `person.last_seen_ts`（最后一次确认检出，见 FR-3.2），而非首帧漏检，避免抖动误触发。

## 6. 功能需求

### 6.1 步骤一：建立连接 + 播放自带动画（对应 M1）
**目标**：验证 Mac↔Cozmo 链路、HAL 最小封装、动画播放。

| 编号 | 需求 |
|---|---|
| FR-1.1 | 用 pycozmo 连接 Cozmo（前置：Cozmo 放充电座唤醒 → 抬放举升显示 Wi-Fi PSK → Mac 连其 Wi-Fi） |
| FR-1.2 | 让 Cozmo 做出一次**可见的表情/情绪表达**。优先尝试播放自带 `.bin` 动画（动画名可配置）；若 SPIKE-1 判定回放不稳定，则降级为"程序化表情 + 背包 LED + 自带音效"实现等效表达。两种实现至少一种满足即可 |
| FR-1.3 | 控制台打印连接成功状态与电池电压 |
| FR-1.4 | 退出时安全断开连接 |
| FR-1.5 | 连接健壮性：检测断连；运行中断连时先**安全停车**（停电机、举升复位），再**自动重连并指数退避**；连续失败超过 `reconnect_max_retries`（默认 5）次后进入"安全停止"状态并告警 |

**验收标准（AC-1）**：运行 `main.py --demo connect` 后，Cozmo 在数秒内做出一次可见的表情/情绪表达（动画或程序化表情+LED+音效二选一），控制台打印连接成功与电池电压。**断连恢复**：在 demo 运行中模拟断连（断开 Wi-Fi 或杀连接），Cozmo 应先停止运动，随后在退避策略内自动重连恢复；若超过最大重试次数则停在"安全停止"并打印告警。

**涉及模块**：`hal/`。

### 6.2 步骤二：自由活动 + 找方块（无线电）玩方块（对应 M2）
**目标**：三层架构真正跑起来；无 LLM 也能动，再叠加 LLM 决策。

任务层 FSM 草案：
```
FREE_ROAM 自由活动
  · 随机游走（前进/转向，受悬崖反射约束）
  · 认知层随机/按规则给一个预设心情 → 播放对应动画
  · 方块已连接 → 可转入 PLAY_CUBE
PLAY_CUBE 玩方块
  · 点亮方块 LED（不同心情不同颜色/节奏）
  · 读方块加速度计：被拍(tapped)/被移动(moved) → 触发 happy/playful 心情与动画
  · 一段时间无互动 → 回到 FREE_ROAM
（任意状态）悬崖/碰撞 → 安全反射立即停 + 后退
```

| 编号 | 需求 |
|---|---|
| FR-2.1 | Cozmo 连上后能自主随机移动（前进/转向） |
| FR-2.2 | **悬崖反射（硬安全，必做）**：感知层读悬崖传感器，触发即立即停 + 后退（不等上层）。**碰撞反射（可选）**：Cozmo 无专用碰撞传感器，以加速度计冲击超阈值 `collision_accel_threshold`（可配置）近似检测；若 SPIKE 验证误报率过高则本阶段降为 Non-Goal，只保留悬崖反射 |
| FR-2.3 | 通过无线电连接方块并感知其状态（connected/tapped/moved），非视觉定位。**连接前置与失败降级**：启动时尝试连接方块；连接失败或无方块时**不阻塞自由活动**，`cube.connected=false`，任务层跳过 PLAY_CUBE 仅做 FREE_ROAM；连接成功后方可转入玩方块 |
| FR-2.4 | 方块被拍/被移动时，在 `cube_react_latency`（默认 1s，可配置）内切到对应心情动画并改变方块 LED。时延计时**起点**为加速度计事件写入黑板（`tapped/moved=true`）的时刻，**终点**为对应动画指令下发 HAL 的时刻。此为关键事件，可打断 MOOD-2 防抖 |
| FR-2.5 | 认知层在预设心情中按权重随机/按简单规则选取并下发任务层 |
| FR-2.6 | 三层各自独立周期运行，黑板字段实时更新（可在日志/调试面板观察） |
| FR-2.7 | **低电量保护**：感知层监测 `battery_voltage`，低于 `battery_low_voltage`（可配置，默认值待 SPIKE 实测电池电压区间后定）时，安全反射进入"停止保护"（停运动、举升复位、可选低电提示表情/LED），回升至 `battery_low_voltage + battery_recover_hysteresis` 以上方解除（滞回防抖）。低电量保护属安全反射优先级（见 ARCH-7 优先级 1），认知层不可覆盖 |

**验收标准（AC-2）**：
- Cozmo 连上后能自主随机移动且遇悬崖会停。
- 方块被拍/被移动时，Cozmo 在 1s 内切到对应心情动画并改变方块 LED（计时口径见 FR-2.4）。
- 无方块或方块连接失败时，Cozmo 仍能正常自由活动，不卡死。
- **低电量保护**：将 `battery_low_voltage` 配置为高于当前电压使其立即触发，Cozmo 应停止运动并进入保护态；调低阈值（或电压回升越过滞回上限）后应解除并恢复活动。
- 三层各自独立周期运行，黑板字段实时更新。

**涉及模块**：`perception/`、`task/`（free_roam、play_cube）、`cognition/`、`world/`、`hal/`、`safety/`。

### 6.3 步骤三：跟人走（MediaPipe Pose + 心情 + 丢人情绪）（对应 M3）
**目标**：人体识别 + 跟随 + 情绪表达 + 丢人后的情绪与搜索。

跟随/搜索 FSM 草案：
```
FOLLOW 跟随
  · 转向控制：根据 cx_norm 把人保持在画面中央（差动转向）
  · 距离控制：根据 size_norm 维持目标区间——太小(远)→前进，太大(近)→停/后退
  · 心情：稳定跟随=calm，靠近/重新找到=happy，边走边播放心情动画
  · person.visible=false 且消失 > T1 → SEARCH（疑惑）
SEARCH 搜索
  · 心情 confused（>T1）→ 左右张望/原地慢转扫描
  · 持续消失 > T2 → 心情升级 anxious（焦急）→ 加快扫描/扩大范围
  · 重新检测到人 → happy 动画 → 回到 FOLLOW
  · （可选）超长时间未找到 → 放弃，回 FREE_ROAM/平静
（任意状态）悬崖/碰撞 → 安全反射立即停
```

| 编号 | 需求 |
|---|---|
| FR-3.1 | 摄像头帧 → MediaPipe Pose 检测人体，输出 `person.visible / cx_norm / size_norm / last_seen_ts` 写入黑板。因 Cozmo 视角极低（贴地仰视），常只能看到人体下半身：**检出部分关键点（可达 `min_visible_keypoints` 个有效关键点，可配置）即视为 visible**，不要求全身。cx_norm 由可见关键点中心估计 |
| FR-3.2 | 检测的进入/退出用可配置帧门限做迟滞确认，减少抖动与误丢失：连续 `visible_enter_frames`（默认 2）帧检出方置 `visible=true`；连续 `lost_exit_frames`（默认 3）帧未检出方置 `visible=false`。`last_seen_ts` 以**最后一次确认检出帧**为准（T1/T2 计时由此起点，见 MOOD-3）。门限默认值须经 SPIKE-2 检出率实测后校准 |
| FR-3.3 | 转向控制：根据 cx_norm 把人保持在画面中央，设**控制死区** `cx_deadband`（|cx_norm| 在死区内不转向）与**角速度上限** `max_angular_speed`（均可配置），避免抖动与高速旋转 |
| FR-3.4 | 距离控制：根据 size_norm 维持目标尺寸区间 `[size_target_low, size_target_high]`（可配置），太远前进、太近停/后退，设**线速度上限** `max_linear_speed`。**size_norm 来源优先取单一稳定指标（肩宽）**；当关键点置信度低或人转身/抬手致测量不可靠时，**不更新距离、保持上一动作**。区间采用**滞回**（进入/退出阈值不同）防止边界抖动——此为显式需求 |
| FR-3.5 | 跟随中持续播放与当前心情匹配的动画（稳定=calm，重新找到=happy） |
| FR-3.6 | 人消失 > T1 进入 SEARCH 并表现疑惑（左右张望/原地慢转） |
| FR-3.7 | 持续消失 > T2 升级 anxious（加快扫描/扩大范围） |
| FR-3.8 | 重新检测到人 → 播放 happy 动画 → 回到 FOLLOW |
| FR-3.9 | （可选）超长时间未找到 → 放弃，回 FREE_ROAM/平静 |
| FR-3.10 | 跟随运动须服从 FR-3.3/3.4 的速度/转速上限与死区；悬崖/低电量安全反射优先于一切跟随运动（见 ARCH-7），不得为追人冲下悬崖或贴近冲撞 |

**验收标准（AC-3）**：
- 人在 Cozmo 前方移动时，能转向并保持朝向人（受死区/速度上限约束，不高速旋转），远近变化时有前进/后退反应。
- 跟随中持续播放与当前心情匹配的动画。
- 人离开画面后，自 `last_seen_ts`（最后确认检出，按 FR-3.2 门限判定）起：达到 `T1`（默认 2s）出现"疑惑"表现，达到 `T2`（默认 5s）升级"焦急"表现；人回来（按 visible 进入门限确认）后播放"开心"动画并恢复跟随。判定以黑板时间戳与状态日志为准。

**涉及模块**：`perception/`（MediaPipe Pose）、`task/`（follow、search）、`cognition/`、`world/`、`hal/`、`safety/`。

### 6.4 认知层 agent loop（对应 M4，第一阶段即接入）
**决策原则**：认知模型决定"意图与心情"，不碰实时控制，并提供规则反射兜底。

| 编号 | 需求 |
|---|---|
| FR-4.1 | 默认**本地 LLM**，运行在 Mac mini；**具体型号由 SPIKE-3 在 M4 实测选定，Gemma 系列优先**。型号/量化/显存为待验证假设（见 11.3），不写死前提 |
| FR-4.2 | 把认知模型封装成统一 **provider 接口** `decide(world_summary[, image]) -> {intention, mood}`，本地默认、云端可选 fallback；更换型号或后端不影响上层 |
| FR-4.3 | 运行模式为事件驱动 + 低频轮询（如每 1–2s 或关键事件触发），非每帧调用 |
| FR-4.4 | 高频意图/心情决策关 thinking 求快；偶发复杂看图理解可开 thinking |
| FR-4.5 | （可选多模态）低频抓一张摄像头快照辅助决策，不进实时环 |
| FR-4.6 | 输入为黑板世界状态摘要（电池、是否看见人/方块、当前心情/意图、关键事件）+ 可选快照 |
| FR-4.7 | 输出为结构化 JSON：`{"intention":..., "mood":..., 可选理由}`。**优先用原生 function calling / 结构化输出**；若 SPIKE-3 判定所选模型不支持原生 function calling，则**降级为受约束的 JSON 生成 + 应用层解析校验**（含非法输出重试/回退到规则兜底）。无论何种方式，非法/超时输出一律走 FR-4.9 兜底 |
| FR-4.8 | 提供工具/动作接口：`set_intention`、`set_mood`、`play_animation`、`get_world_state`；工具只改目标/心情，由任务层执行，模型不直接发电机指令。原生 function calling 不可用时，以等价的 JSON 字段表达同一组动作 |
| FR-4.9 | 必须有反射兜底：模型未返回/超时/不可达时给默认意图与心情（看见人→follow，人丢→T1 疑惑/T2 焦急，低电量→停）；模型返回后可覆盖，但安全反射不可被覆盖 |
| FR-4.10 | 本阶段不做 TTS，心情靠表情/动画/Cozmo 自带音效表达 |

**验收标准（AC-4）**：模型能下发意图/心情；当超时/不可达时由规则兜底维持机器人正常运行。

## 7. 非功能需求（NFR）

| 编号 | 需求 |
|---|---|
| NFR-1 安全 | 悬崖安全反射在感知层本层闭环、立即响应，不可被认知层覆盖（碰撞反射为可选，见 FR-2.2）；低电量按 FR-2.7 阈值+滞回进入停止保护 |
| NFR-2 实时性 | 感知层目标 ～30Hz、任务层 ～10Hz、认知层 ～秒级；LLM 不得进入实时控制环。**感知 30Hz 与控制延迟预算为待验证目标，由 SPIKE-4 实测确认，达不到则下调节拍**（见 11.3） |
| NFR-3 鲁棒性 | 认知模型慢/断网/超时由规则兜底；pycozmo 断连按 FR-1.5 重连与异常恢复 |
| NFR-4 资源 | 本地模型在 32GB Mac mini 上与 MediaPipe、pycozmo 共存，须监控内存峰值与首字延迟；具体显存占用与降配方案由 SPIKE-3 实测确定（型号/量化为待验证假设，见 11.3） |
| NFR-5 可配置 | 所有阈值与控制参数集中在 `config.yaml`，至少含：丢人阈值 `T1/T2`、`mood_min_hold`；`visible_enter_frames`/`lost_exit_frames`/`min_visible_keypoints`；`size_target_low/high` 及其滞回、`cx_deadband`、`max_linear_speed`/`max_angular_speed`；`battery_low_voltage`/`battery_recover_hysteresis`、`collision_accel_threshold`、`cube_react_latency`；`reconnect_max_retries` 及退避参数；LLM 轮询周期/超时、provider/型号、动画名、网络。各项须有默认值（部分默认值待 SPIKE 实测校准） |
| NFR-6 可测试 | HAL 可 mock，三层可在无实体硬件下做集成测试 |
| NFR-7 可观测 | 建议提供调试面板/日志实时查看黑板状态，便于联调 |
| NFR-8 可扩展 | provider 接口可切云端；心情系统后续可升级为带强度的情绪模型；预留 TTS 组件位 |

## 11. 风险与未决项

### 11.1 风险
| 风险 | 等级 | 说明 | 缓解 |
|---|---|---|---|
| **低视角全身检测困难** | **最高** | Cozmo 贴地仰视，MediaPipe 常只见下半身，检出率/抖动未知 | **SPIKE-2 列为 M3 前最高风险**；放宽为部分关键点即 visible（FR-3.1）+ 帧门限迟滞（FR-3.2） |
| 并发竞态 | 高 | 多层并发读写黑板可能撕裂/死锁，阻塞实时节拍 | 写者唯一+一致快照（ARCH-6）、并发隔离（ARCH-5） |
| Wi-Fi 图传带宽/延迟制约 30Hz | 高 | 帧经 Wi-Fi 回传 Mac，端到端可能达不到 30Hz | SPIKE-4 实测，达不到则下调节拍（NFR-2） |
| 跟随时运动模糊降低检出 | 中 | 机器人运动致画面模糊，漏检上升 | 限速（FR-3.3/3.4）+ 低置信度保持上一动作 |
| 单目测距不精确 | 中 | 跟随距离只能近似，靠尺寸区间控制，可能抖动 | 视觉伺服 + 单一稳定指标(肩宽) + 区间滞回（FR-3.4） |
| 摄像头分辨率/帧率低 | 中 | 实测约 320×240 灰度、~15fps，待 SPIKE-2 确认 | 多帧确认与平滑，降低误丢失 |
| 本地模型资源占用 | 中 | 型号/显存待定，与感知/pycozmo 同台 | SPIKE-3 监控峰值与首字延迟，必要时降配 |
| `.bin` 动画回放支持不完整 | 中 | pycozmo 回放稳定性未知 | SPIKE-1 验证，不稳定则降级程序化表情+LED+音效（FR-1.2） |
| 本地 LLM 工具链成熟度 | 中 | function calling/JSON 约束/多模态成熟度未知 | SPIKE-3 验证，不支持原生 function calling 则降级 JSON 解析（FR-4.7） |
| pycozmo 稳定性 | 中 | 官方自述"不稳定、开发中" | 重连与异常恢复机制（FR-1.5） |
| 自带动画名未定 | 低 | 各动画确切 `.bin` 名需实现时选定 | 做成可配置，先占位后替换 |

### 11.2 已确认的关键决策
- 找方块：用方块无线电交互（加速度计/LED），不做视觉定位。
- 跟人：MediaPipe Pose 人体检测（实时跟随专用，不用大模型；接受仅检出部分关键点）。
- 认知层：第一阶段即接入，用**本地 LLM**（型号待 SPIKE-3 选定，Gemma 系列优先）。
- 网络：本地模型，无需外网/第二网卡；模型与依赖须预先缓存（C5）。
- 语音：本阶段暂不做 TTS。
- 心情：固定预设几种心情 → 映射到自带动画（不做数值衰减）。

### 11.3 待确认的假设（评审时修订）
1. 丢人阈值 `T1=2s`（疑惑）/ `T2=5s`（焦急）是否合适？
2. 预设心情集合（calm/happy/playful/curious/confused/anxious）是否够用、命名是否 OK？
3. **本地 LLM 选型**：型号/量化/是否需带音频输入（如能"听声音"的多模态变体）由 SPIKE-3 实测后定，Gemma 系列优先——是否有指定偏好或硬性约束？
4. M1 播放的"自带动画"是否有指定偏好（打招呼/开心/任意）？
5. 是否需要一个简单的调试面板/日志实时查看黑板状态（建议有）？
6. **低电量阈值**：`battery_low_voltage` 与滞回回升量取值需实测电池电压区间后定——是否有偏好的保护触发点（偏保守/偏续航）？
7. **碰撞反射是否保留**：Cozmo 无专用碰撞传感器，以加速度计近似可能误报。第一阶段保留（可配阈值）还是降为 Non-Goal、仅留悬崖硬安全？
8. **感知节拍目标**：若 SPIKE-4 实测 Wi-Fi 图传端到端达不到 30Hz，可接受的感知/控制节拍下限是多少？
