# Cozmo「跟人走」第一阶段 —— 需求与设计构想（follow-me-idea）

> 状态：构想 / 待评审
> 范围：第一阶段三步（建立连接 → 自由活动 → 跟人走）
> 平台：Mac mini + 实体 Cozmo，底层使用 [pycozmo](https://github.com/zayfod/pycozmo)
> 最终目标：跑通三层架构，让 Cozmo 能识别人并跟随，带情绪表达。

---

## 0. 目标概述

第一阶段分三步递进，每一步都能独立产出"可运行的 demo"：

1. **建立连接**：应用连上 Cozmo，并在 Cozmo 上播放一段自带的表情/动作动画，证明链路打通。
2. **自由活动**：搭起三层架构；Cozmo 连上后能自行随机活动，通过**无线电**找到并和它的方块玩，随机进入一种预设心情。
3. **跟人走**：用 MediaPipe Pose 做人体识别并跟随人；跟随时带预设心情、边走边播放心情动画；**人不见了时产生心情变化（疑惑 → 焦急）**。

贯穿三步的能力底座：**三层架构 + 心情系统 + LLM 认知层**。

## 1. 技术前提与约束（务必先读）

### 1.1 pycozmo 能力边界
pycozmo 替代 Cozmo App 作为底层引擎，**给底层硬件控制，不给高层智能**：

- ✅ 提供：车轮/头部/举升电机、摄像头图像流、程序化表情（眼睛开合/表情参数）、`.bin` 动画播放、WAV 音频播放（22kHz/16bit/单声道）、背包 LED、**方块 LED 与方块加速度计**、悬崖/加速度/陀螺仪/电池电压传感器。
- ❌ **未实现**：人脸/人体检测、**视觉方块/标记识别**、物体识别、地图构建、TTS、自动充电对接。这些都要在 Mac 端自己做。

### 1.2 由此产生的关键设计取舍
- **找方块不靠视觉**：Cozmo 看不到方块。方块通过**无线电**与机器人通信。"找方块/玩方块"= 随机移动 + 点亮方块 LED + 读方块加速度计（被拍/被移动）来交互，而非视觉定位。
- **人体识别在 Mac 端做**：摄像头帧传到 Mac，用 **MediaPipe Pose** 检测人体骨架，估计人在画面中的水平位置与远近（用躯干/肩宽或包围盒高度近似距离）。
- **单目测距**：Cozmo 只有单摄像头，距离是"近似估计"，跟随用"保持目标在画面中央 + 维持一个尺寸区间"的视觉伺服，而非精确测距。

### 1.3 网络：本地模型，无需外网
认知层用**本地模型**（Gemma 4，跑在 Mac mini 上，见第 7 节），因此**不依赖外网**——Wi‑Fi 可以一直连着 Cozmo，**无需第二张网卡**。这是选本地模型的一大好处（早期方案曾担心的"双网卡硬约束"由此消除）。
- 连 Cozmo 的 Wi‑Fi（PSK）仍会占用 Mac 的无线网卡，连着时上不了外网；因认知层本地化，这不影响运行。
- 仅当将来切换到**云端模型**时，才需要第二条网络（USB‑以太网/第二网卡）。无论本地还是云端，软件对"认知模型暂时不可达/超时"都有反射兜底（见第 7 节）。

## 2. 三层架构总览（Gat 1998 三层模型 / BDI）

> 核心原则：**每层不同周期，LLM 永不进实时控制环**。下层向上报"事实"，上层向下发"目标"，通过**共享黑板（Blackboard / Belief store）**解耦。

```
┌──────────────────────────────────────────────────────────┐
│ 认知层 Deliberator —— LLM agent loop    ～秒级 / 事件驱动        │
│  · 读 Belief（世界状态摘要）                                    │
│  · 决定 Intention（目标）与 Mood（心情）→ 下发任务层              │
│  · 例：「去找方块玩」「跟住这个人」「人丢了，进入焦急并搜索」          │
│  · 规则反射兜底：LLM 慢/断网时由规则给出默认意图                   │
└───────────────▲──────────────────────────┬───────────────┘
         Belief 摘要 │                          │ Goal + Mood
┌───────────────┴──────────────────────────▼───────────────┐
│ 任务层 Sequencer —— 状态机/行为      ～10Hz                     │
│  · 用 FSM 执行当前目标：自由活动FSM / 玩方块FSM / 跟随FSM         │
│  · 用感知事实做状态转移，向 HAL 下电机/表情/声音/LED 指令          │
│  · 把当前 Mood 落到具体动画与行为强度                            │
└───────────────▲──────────────────────────┬───────────────┘
            Facts │                          │ 电机/表情/声音/LED
┌───────────────┴──────────────────────────▼───────────────┐
│ 感知层 Reactive —— 实时        ～30Hz / 回调                   │
│  · 摄像头帧 → MediaPipe Pose（人体）；方块加速度计；电池；姿态     │
│  · 安全反射（悬崖/碰撞→立即停）在本层闭环，不等上层                 │
│  · 把"事实"写入黑板                                            │
└──────────────────────────────────────────────────────────┘
                         ▲
                         │
            HAL（硬件抽象层，封装 pycozmo）
```

### 2.1 黑板（World / Belief store）
层间唯一共享状态。建议字段（草案）：

```
world = {
  "timestamp": float,
  "battery_voltage": float,
  "pose": {"x","y","angle"},
  "cliff_detected": bool,
  "person": {
     "visible": bool,
     "cx_norm": float,        # 人体中心在画面的水平归一化位置 [-1,1]
     "size_norm": float,      # 包围盒/肩宽归一化，近似远近
     "last_seen_ts": float,
  },
  "cube": {
     "connected": bool,
     "tapped": bool,          # 来自加速度计
     "moved": bool,
  },
  "mood": "calm|happy|playful|curious|confused|anxious",
  "intention": "free_roam|play_cube|follow_person|search_person|...",
}
```

## 3. 心情系统（固定预设 → 映射动画）

第一阶段采用**有限的预设心情**，每种映射到 Cozmo 自带的 `.bin` 动画 + 表情 + 背包 LED。**不做数值衰减**（后续阶段可升级为带强度的情绪模型）。

| 心情 mood | 触发场景 | 表达（待确认具体动画名） |
|---|---|---|
| `calm` 平静 | 默认/待机、稳定跟随 | 轻微待机表情，呼吸式眨眼 |
| `happy` 开心 | 找到人/方块、互动成功 | 自带 happy/excited 动画 + 绿色 LED |
| `playful` 顽皮 | 自由活动玩方块 | 自带 playful 动画，点亮方块 LED |
| `curious` 好奇 | 发现新目标、扫描中 | 头部转动 + 好奇表情 |
| `confused` 疑惑 | 人短暂消失（>T1） | 自带 confused/搜寻动画，左右张望 |
| `anxious` 焦急 | 人长时间消失（>T2） | 急促表情 + 黄/红 LED + 加快搜索 |

- 心情由**认知层决定并写入黑板**；任务层负责把心情**翻译成动画与行为强度**。
- 心情切换要有**最短保持时间**（防抖），避免动画频繁打断。
- 默认阈值（待确认）：`T1 = 2s`（人消失→疑惑），`T2 = 5s`（持续消失→焦急）。

## 4. 步骤一：建立连接 + 播放自带表情动画

**目标**：验证 Mac↔Cozmo 链路、HAL 最小封装、动画播放。

**做什么**
- 用 pycozmo 连接 Cozmo（前置：Cozmo 放充电座唤醒 → 抬放举升显示 Wi‑Fi PSK → Mac 连其 Wi‑Fi）。
- 加载并播放一段**自带 `.bin` 表情/动作动画**（如开心/打招呼系列，具体动画名在实现时从 pycozmo 资源中选定，做成可配置）。
- 退出时安全断开。

**验收标准**
- 运行 `main.py --demo connect` 后，Cozmo 在数秒内播放一段可见的表情/动作动画，控制台打印连接成功与电池电压。

**涉及模块**：`hal/`（连接、播放动画的薄封装）。

## 5. 步骤二：自由活动 + 找方块（无线电）玩方块

**目标**：三层架构真正跑起来；无 LLM 也能动，再叠加 LLM 决策。

**行为设计（任务层 FSM 草案）**
```
FREE_ROAM 自由活动
  · 随机游走（前进/转向，受悬崖反射约束）
  · 认知层随机/按规则给一个预设心情 → 播放对应动画
  · 方块已连接 → 可转入 PLAY_CUBE
PLAY_CUBE 玩方块
  · 点亮方块 LED（不同心情不同颜色/节奏）
  · 读方块加速度计：被拍(tapped)/被移动(moved) → 触发 happy/playful 心情与动画
  · 一段时间无互动 → 回到 FREE_ROAM
（任意状态）悬崖/碰撞 → 安全反射立即停 + 后退
```

**说明**
- "找方块"= 通过无线电连接方块并感知其状态，**不是视觉定位**；机器人随机活动期间用方块 LED + 加速度计做"互动游戏"。
- 随机心情：第一阶段认知层可在若干预设心情中按权重随机/按简单规则选取，并下发任务层。

**验收标准**
- Cozmo 连上后能自主随机移动且遇悬崖会停。
- 方块被拍/被移动时，Cozmo 在 1s 内切到对应心情动画并改变方块 LED。
- 三层各自独立周期运行，黑板字段实时更新（可在日志/调试面板观察）。

**涉及模块**：`perception/`（方块状态、悬崖、姿态）、`task/`（free_roam、play_cube FSM）、`cognition/`（心情选择）、`world/`、`hal/`、`safety/`。

## 6. 步骤三：跟人走（MediaPipe Pose + 心情 + 丢人→疑惑/焦急）

**目标**：人体识别 + 跟随 + 情绪表达 + 丢人后的情绪与搜索。

**感知**
- 摄像头帧 → **MediaPipe Pose** 检测人体；输出 `person.visible / cx_norm / size_norm / last_seen_ts` 写入黑板。
- 注意 Cozmo 摄像头分辨率/帧率有限，需对检测做**多帧确认与平滑**，减少抖动与误丢失。

**跟随控制（任务层 FSM 草案）**
```
FOLLOW 跟随
  · 转向控制：根据 cx_norm 把人保持在画面中央（差动转向）
  · 距离控制：根据 size_norm 维持目标区间——太小(远)→前进，太大(近)→停/后退
  · 心情：稳定跟随=calm，靠近/重新找到=happy，边走边播放心情动画
  · person.visible=false 且消失 > T1 → SEARCH（疑惑）
SEARCH 搜索
  · 心情 confused（>T1）→ 左右张望/原地慢转扫描
  · 持续消失 > T2 → 心情升级 anxious（焦急）→ 加快扫描/扩大范围
  · 重新检测到人 → happy 动画 → 回到 FOLLOW
  · （可选）超长时间未找到 → 放弃，回 FREE_ROAM/平静
（任意状态）悬崖/碰撞 → 安全反射立即停
```

**验收标准**
- 人在 Cozmo 前方移动时，Cozmo 能转向并保持朝向人，远近变化时有前进/后退反应。
- 跟随中持续播放与当前心情匹配的动画。
- 人离开画面：~2s 内出现"疑惑"表现，~5s 后升级为"焦急"表现；人回来后播放"开心"动画并恢复跟随。

**涉及模块**：`perception/`（MediaPipe Pose）、`task/`（follow、search FSM）、`cognition/`（心情/意图）、`world/`、`hal/`、`safety/`。

## 7. 认知层 agent loop 设计（第一阶段即接入，本地 Gemma 4）

> 决策原则：**认知模型决定"意图与心情"，不碰实时控制**；并提供**规则反射兜底**，保证模型慢/超时时机器人照常运行。

- **模型与运行**：默认 **本地 Gemma 4 26B‑A4B（4-bit 量化，Ollama）**，跑在 Mac mini 上（Apple Silicon / 32GB）。MoE 架构只激活 ~4B，推理快、占用约 18GB，余量充足。
- **provider 可切换**：把认知模型封装成统一接口 `decide(world_summary[, image]) -> {intention, mood}`，本地 Ollama 为默认，云端模型作为可选 fallback（切云端才需第 1.3 节的第二网络）。
- **运行模式**：事件驱动 + 低频轮询（如每 1–2s 或关键事件触发一次），**不是每帧调用**，以控延迟与算力。
- **thinking 模式**：高频的意图/心情决策走**关 thinking**（求快）；偶发的复杂看图理解再**开 thinking**。
- **多模态（可选）**：Gemma 4 支持图像输入，认知层可**低频抓一张摄像头快照**让模型理解场景/认人辅助决策（不进实时环；实时跟随仍由 MediaPipe Pose 负责）。
- **输入**：黑板的**世界状态摘要**（电池、是否看见人/方块、当前心情/意图、关键事件）+ 可选快照。
- **输出（结构化 / 原生 JSON + function calling）**：下一步 `intention` + `mood`（+ 可选简短理由）。例如 `{"intention":"search_person","mood":"anxious"}`。Gemma 4 原生支持 JSON 结构化输出与工具调用，约束输出可靠。
- **工具接口（function calling，把"机器人能力"暴露给模型）**草案：
  - `set_intention(intention)`、`set_mood(mood)`
  - `play_animation(name)`、`get_world_state()`
  - 注意：这些工具改变的是**目标/心情**，由任务层去实际执行，模型不直接发电机指令。
- **反射兜底（必须有）**：一套确定性规则，在模型未返回前/超时/不可达时给出默认意图与心情（如"看见人→follow"，"人丢→T1 疑惑/T2 焦急"，"低电量→停"）。模型返回后可覆盖（但安全反射不可被覆盖）。
- **语音**：本阶段**不做 TTS**（Gemma 只输出文本，不出声），心情靠表情/动画/Cozmo 自带音效表达；语音留作后续增强（届时单列一个 TTS 组件，文本→WAV→pycozmo 播放）。

| 里程碑 | 内容 | 验收 |

| M1 连接 | HAL + 播放自带动画 | `--demo connect` 播放动画、打印电量 |

## 10. 风险与未决项

- **单目测距不精确**：跟随距离只能近似，靠尺寸区间控制，可能抖动。
- **Cozmo 摄像头分辨率/帧率低**：MediaPipe Pose 在低质画面上可能漏检；需多帧平滑。
- **本地模型资源占用**：Gemma 4 26B‑A4B（4-bit）约占 18GB 内存，需与感知（MediaPipe）、pycozmo 等同台共存；32GB 够用但需关注峰值与首字延迟，必要时降到 E4B。
- **Gemma 4 较新（2026‑04 发布）**：本地工具链（Ollama/MLX）与多模态/JSON 约束的成熟度需在 M4 实测验证。
- **pycozmo 稳定性**：官方自述"不稳定、开发中"，需要重连与异常恢复。
- **具体自带动画名**：M1 的表情动画、各心情动画的确切 `.bin` 名称需在实现时从 pycozmo 资源里选定并做成可配置。

## 11. 已确认的关键决策（来自需求澄清）

- 找方块：**用方块无线电交互（加速度计/LED），不做视觉定位**。
- 跟人：**MediaPipe Pose 全身检测**（实时跟随专用，不用大模型）。
- 认知层：**第一阶段即接入**，用**本地 Gemma 4 26B‑A4B（Ollama）**（按本文第 7 节：意图/心情决策 + 规则兜底，不进实时环，多模态看图可选，provider 可切换）。
- 网络：**本地模型，无需外网/第二网卡**（见 1.3）。
- 语音：**本阶段暂不做 TTS**（Cozmo 不说话），心情靠表情/动画/自带音效；语音留作后续增强。
- 心情：**固定预设几种心情 → 映射到自带动画**（不做数值衰减）。

## 12. 待你确认的假设（可在评审时修订）

1. 丢人阈值 `T1=2s`（疑惑）/ `T2=5s`（焦急）是否合适？
2. 预设心情集合（calm/happy/playful/curious/confused/anxious）是否够用、命名是否 OK？
3. Gemma 4 默认 **26B‑A4B**；若更看重"让 Cozmo 能听声音"，是否改用带音频输入的 **E4B**？
4. M1 播放的"自带动画"是否有指定偏好（打招呼/开心/任意）？
5. 是否需要一个简单的**调试面板/日志**实时查看黑板状态（建议有，便于联调）？
