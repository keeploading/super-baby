## 1. 文档说明

### 1.1 编写目的

本文档将 `docs/ideas/follow-me-idea.md` 中的产品构想，转化为一份可指导研发与测试落地的**需求设计文档**：明确各步骤要**做什么（功能边界）**、**做成什么样（设计约束）**、**怎么验收（验收标准）**，为后续详细技术设计与排期提供依据。

构想文档侧重"想法与论证"，本文档侧重"结构化需求 + 设计约束 + 可验收项"，二者互补。当两者冲突时，以本文档为准并回写更新构想文档。

### 1.2 读者对象

- 项目负责人：确认范围、优先级与里程碑
- 研发工程师（感知 / 任务 / 认知 / HAL）：作为开发依据
- 测试工程师：作为测试用例与验收依据

### 1.3 需求优先级约定（MoSCoW）

| 标记 | 含义 | 说明 |
| --- | --- | --- |
| **M** (Must) | 必须有 | 第一阶段必备，缺失则目标不成立 |
| **S** (Should) | 应该有 | 重要但可在阶段内迭代补齐 |
| **C** (Could) | 可以有 | 锦上添花 |
| **W** (Won't) | 暂不做 | 明确划出本阶段范围之外（如 TTS） |

## 2. 产品目标与范围

### 2.1 一句话目标

**跑通"感知—任务—认知"三层架构，让实体 Cozmo 能在本地识别并跟随人、与方块互动，并通过心情系统表达情绪。**

### 2.2 第一阶段三步（递进，每步可独立 demo）

| 步骤 | 名称 | 产出 |
| --- | --- | --- |
| **步骤一** | 建立连接 | 应用连上 Cozmo 并播放一段自带表情/动作动画，证明链路打通 |
| **步骤二** | 自由活动 | 三层架构跑起来；Cozmo 自主随机活动，通过**无线电**找到并与方块互动，进入预设心情 |
| **步骤三** | 跟人走 | 用 MediaPipe Pose 识别并跟随人；带心情、边走边播动画；**人丢失时情绪变化（疑惑 → 焦急）** |

贯穿三步的能力底座：**三层架构 + 心情系统 + 本地 LLM 认知层**。

### 2.3 本阶段不做（非目标）

- ❌ **不做 TTS / 让 Cozmo 说话**（心情靠表情/动画/自带音效表达，语音留作后续增强）。
- ❌ **不做视觉方块识别/定位**（方块通过无线电交互，见 §4）。
- ❌ **不做精确测距/地图构建**（单目，仅近似尺寸伺服）。
- ❌ **不做情绪数值衰减模型**（本阶段为有限预设心情）。
- ❌ **不依赖外网/云端模型**（默认本地模型，见 §4.3）。

## 3. 术语与约定

| 术语 | 含义 |
| --- | --- |
| HAL | 硬件抽象层，封装 pycozmo 的薄抽象（电机/表情/声音/LED/方块/连接） |
| 黑板 / Belief store | 层间唯一共享状态（World / 信念库） |
| 感知层 Reactive | 实时层（~30Hz / 回调），产出"事实"写入黑板 |
| 任务层 Sequencer | 状态机/行为层（~10Hz），执行当前目标 |
| 认知层 Deliberator | LLM agent loop（~秒级 / 事件驱动），决定意图与心情 |
| Intention 意图 | 认知层下发的目标（如 follow_person、search_person） |
| Mood 心情 | 预设情绪状态，映射到动画/LED/行为强度 |
| 安全反射 | 在感知层就地闭环的紧急处理（悬崖/碰撞→立即停），不可被上层覆盖 |
| 视觉伺服 | 通过保持目标在画面中央 + 维持尺寸区间来控制跟随 |

## 4. 技术前提与约束

> 本章为**硬约束**，所有设计必须遵守。来源于 pycozmo 能力边界与单目硬件限制。

### 4.1 pycozmo 能力边界

pycozmo 替代 Cozmo App 作为底层引擎，**只给底层硬件控制，不给高层智能**：

- ✅ **提供**：车轮/头部/举升电机、摄像头图像流、程序化表情（眼睛开合/表情参数）、`.bin` 动画播放、WAV 音频播放（22kHz/16bit/单声道）、背包 LED、**方块 LED 与方块加速度计**、悬崖/加速度/陀螺仪/电池电压传感器。
- ❌ **未实现**（需在 Mac 端自己做）：人脸/人体检测、**视觉方块/标记识别**、物体识别、地图构建、TTS、自动充电对接。

### 4.2 由此产生的关键设计取舍

| 约束编号 | 约束 |
| --- | --- |
| CON-01 | **找方块不靠视觉**：方块经无线电通信；"找方块/玩方块" = 随机移动 + 点亮方块 LED + 读方块加速度计（被拍/被移动）交互。 |
| CON-02 | **人体识别在 Mac 端做**：摄像头帧传到 Mac，用 **MediaPipe Pose** 检测人体骨架，估计水平位置与远近。 |
| CON-03 | **单目近似测距**：跟随采用"保持目标居中 + 维持尺寸区间"的视觉伺服，不做精确测距。 |
| CON-04 | **LLM 永不进实时控制环**：认知层只决定意图与心情，实时控制由任务层/感知层负责。 |

### 4.3 网络：本地模型，无需外网

- 认知层默认使用**本地模型**（Gemma 4，跑在 Mac mini 上，见 §9），**不依赖外网**——连 Cozmo 的 Wi-Fi 即可，**无需第二张网卡**。
- 连 Cozmo 的 Wi-Fi（PSK）会占用 Mac 无线网卡、连着时上不了外网；因认知层本地化，不影响运行。
- 仅当将来切换到**云端模型**时，才需要第二条网络（USB-以太网/第二网卡）。
- 无论本地还是云端，软件对"认知模型暂时不可达/超时"都必须有**反射兜底**（见 §9）。

## 5. 总体架构设计

采用 **Gat 1998 三层模型 / BDI**。核心原则：**每层不同周期，下层报"事实"、上层发"目标"，通过共享黑板解耦；LLM 永不进实时环。**

```
┌──────────────────────────────────────────────────────────┐
│ 认知层 Deliberator —— LLM agent loop    ～秒级 / 事件驱动        │
│  · 读 Belief 摘要 → 决定 Intention + Mood → 下发任务层          │
│  · 规则反射兜底：LLM 慢/断网时由规则给默认意图                    │
└───────────────▲──────────────────────────┬───────────────┘
         Belief 摘要 │                          │ Goal + Mood
┌───────────────┴──────────────────────────▼───────────────┐
│ 任务层 Sequencer —— 状态机/行为      ～10Hz                     │
│  · FSM 执行目标：free_roam / play_cube / follow / search       │
│  · 用感知事实做状态转移；下发电机/表情/声音/LED 指令              │
│  · 把 Mood 落到具体动画与行为强度                               │
└───────────────▲──────────────────────────┬───────────────┘
            Facts │                          │ 电机/表情/声音/LED
┌───────────────┴──────────────────────────▼───────────────┐
│ 感知层 Reactive —— 实时        ～30Hz / 回调                   │
│  · 摄像头帧→MediaPipe Pose；方块加速度计；电池；姿态             │
│  · 安全反射（悬崖/碰撞→立即停）本层闭环，不等上层                 │
│  · 把"事实"写入黑板                                            │
└──────────────────────────────────────────────────────────┘
                         ▲
            HAL（硬件抽象层，封装 pycozmo）
```

### 5.1 架构需求

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| F-ARCH-01 | 三层各自独立周期运行（感知 ~30Hz、任务 ~10Hz、认知 ~秒级/事件驱动） | M |
| F-ARCH-02 | 层间仅通过黑板共享状态，不直接耦合调用 | M |
| F-ARCH-03 | HAL 封装 pycozmo，使上层可对 HAL 进行 mock 测试 | M |
| F-ARCH-04 | 即使认知层缺席（未接入/超时），任务层 + 规则兜底也能独立跑通 | M |

## 6. 黑板（世界状态）数据设计

层间唯一共享状态。字段草案：

```python
world = {
  "timestamp": float,
  "battery_voltage": float,
  "pose": {"x": float, "y": float, "angle": float},
  "cliff_detected": bool,
  "person": {
     "visible": bool,
     "cx_norm": float,        # 人体中心水平归一化位置 [-1, 1]
     "size_norm": float,      # 包围盒/肩宽归一化，近似远近
     "last_seen_ts": float,
  },
  "cube": {
     "connected": bool,
     "tapped": bool,          # 来自加速度计
     "moved": bool,
  },
  "mood": "calm|happy|playful|curious|confused|anxious",
  "intention": "free_roam|play_cube|follow_person|search_person|...",
}
```

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| F-WORLD-01 | 黑板提供线程/进程安全的读写，供三层并发访问 | M |
| F-WORLD-02 | 感知层实时更新 person / cube / 传感器字段 | M |
| F-WORLD-03 | 认知层写入 mood / intention，任务层读取并执行 | M |
| F-WORLD-04 | 关键字段可在调试面板/日志实时观察（见 NFR） | S |

## 7. 心情系统设计

第一阶段采用**有限预设心情**，每种映射到 Cozmo 自带 `.bin` 动画 + 表情 + 背包 LED；**不做数值衰减**。

| 心情 mood | 触发场景 | 表达（具体动画名待实现时选定） |
| --- | --- | --- |
| `calm` 平静 | 默认/待机、稳定跟随 | 轻微待机表情，呼吸式眨眼 |
| `happy` 开心 | 找到人/方块、互动成功 | happy/excited 动画 + 绿色 LED |
| `playful` 顽皮 | 自由活动玩方块 | playful 动画，点亮方块 LED |
| `curious` 好奇 | 发现新目标、扫描中 | 头部转动 + 好奇表情 |
| `confused` 疑惑 | 人短暂消失（> T1） | confused/搜寻动画，左右张望 |
| `anxious` 焦急 | 人长时间消失（> T2） | 急促表情 + 黄/红 LED + 加快搜索 |

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| F-MOOD-01 | 心情由认知层决定并写入黑板 | M |
| F-MOOD-02 | 任务层负责把心情翻译成具体动画、LED 与行为强度 | M |
| F-MOOD-03 | 心情切换设**最短保持时间**（防抖），避免动画频繁打断 | M |
| F-MOOD-04 | 心情→动画/LED 的映射表可配置（`moods/` + `config.yaml`） | S |
| F-MOOD-05 | 默认阈值可配置：`T1 = 2s`（消失→疑惑），`T2 = 5s`（持续消失→焦急） | M |

## 8. 功能需求详述

### 8.1 步骤一：建立连接 + 播放自带动画

**目标**：验证 Mac↔Cozmo 链路、HAL 最小封装、动画播放。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| F-S1-01 | 用 pycozmo 连接 Cozmo（前置：充电座唤醒 → 抬放举升显示 Wi-Fi PSK → Mac 连其 Wi-Fi） | M |
| F-S1-02 | 加载并播放一段自带 `.bin` 表情/动作动画（动画名可配置） | M |
| F-S1-03 | 控制台打印连接成功与电池电压 | M |
| F-S1-04 | 退出时安全断开连接 | M |

**验收**：运行 `main.py --demo connect` 后，Cozmo 数秒内播放可见动画，控制台打印连接成功与电量。
**涉及模块**：`hal/`。

### 8.2 步骤二：自由活动 + 找方块（无线电）玩方块

**目标**：三层架构真正跑起来；无 LLM 也能动（规则兜底），再叠加 LLM 决策。

**任务层 FSM 草案**
```
FREE_ROAM 自由活动
  · 随机游走（前进/转向，受悬崖反射约束）
  · 认知层随机/按规则给一个预设心情 → 播放对应动画
  · 方块已连接 → 可转入 PLAY_CUBE
PLAY_CUBE 玩方块
  · 点亮方块 LED（不同心情不同颜色/节奏）
  · 读方块加速度计：tapped/moved → 触发 happy/playful 心情与动画
  · 一段时间无互动 → 回 FREE_ROAM
（任意状态）悬崖/碰撞 → 安全反射立即停 + 后退
```

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| F-S2-01 | Cozmo 连上后能自主随机移动（前进/转向） | M |
| F-S2-02 | 遇悬崖会立即停（安全反射） | M |
| F-S2-03 | 通过无线电连接方块并读取其加速度计状态（tapped/moved） | M |
| F-S2-04 | 方块被拍/被移动时，1s 内切到对应心情动画并改变方块 LED | M |
| F-S2-05 | 三层各自独立周期运行，黑板字段实时更新且可观察 | M |
| F-S2-06 | 心情可由认知层在预设集合中按权重随机/规则选取并下发 | S |

**涉及模块**：`perception/`、`task/`（free_roam、play_cube）、`cognition/`、`world/`、`hal/`、`safety/`。

### 8.3 步骤三：跟人走（MediaPipe Pose + 心情 + 丢人情绪）

**目标**：人体识别 + 跟随 + 情绪表达 + 丢人后的情绪与搜索。

**任务层 FSM 草案**
```
FOLLOW 跟随
  · 转向：据 cx_norm 把人保持在画面中央（差动转向）
  · 距离：据 size_norm 维持区间——太小(远)→前进，太大(近)→停/后退
  · 心情：稳定跟随=calm，靠近/重新找到=happy，边走边播心情动画
  · person.visible=false 且消失 > T1 → SEARCH（疑惑）
SEARCH 搜索
  · confused（> T1）→ 左右张望/原地慢转扫描
  · 持续消失 > T2 → 升级 anxious（焦急）→ 加快扫描/扩大范围
  · 重新检测到人 → happy 动画 → 回 FOLLOW
  · （可选）超长时间未找到 → 放弃，回 FREE_ROAM/平静
（任意状态）悬崖/碰撞 → 安全反射立即停
```

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| F-S3-01 | 摄像头帧 → MediaPipe Pose 检测人体，输出 person 字段写入黑板 | M |
| F-S3-02 | 对检测做多帧确认与平滑，减少抖动与误丢失 | M |
| F-S3-03 | 据 cx_norm 转向，使人保持画面中央 | M |
| F-S3-04 | 据 size_norm 控制前进/后退，维持目标尺寸区间 | M |
| F-S3-05 | 跟随中持续播放与当前心情匹配的动画 | M |
| F-S3-06 | 人消失 > T1（~2s）出现疑惑表现 | M |
| F-S3-07 | 人持续消失 > T2（~5s）升级为焦急表现 | M |
| F-S3-08 | 人重新出现后播放开心动画并恢复跟随 | M |
| F-S3-09 | （可选）超长未找到 → 放弃回到自由活动 | C |

**涉及模块**：`perception/`（MediaPipe Pose）、`task/`（follow、search）、`cognition/`、`world/`、`hal/`、`safety/`。

## 9. 认知层（Agent Loop）设计

> 原则：**认知模型决定"意图与心情"，不碰实时控制**；并提供**规则反射兜底**，模型慢/超时时机器人照常运行。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| F-COG-01 | 默认本地 **Gemma 4 26B-A4B（4-bit 量化，Ollama）**，跑在 Mac mini 上 | M |
| F-COG-02 | 封装统一接口 `decide(world_summary[, image]) -> {intention, mood}`，provider 可切换（本地默认，云端可选 fallback） | M |
| F-COG-03 | 事件驱动 + 低频轮询（如每 1–2s 或关键事件触发），**非每帧调用** | M |
| F-COG-04 | 高频意图/心情决策**关 thinking**（求快）；偶发复杂看图理解再开 thinking | S |
| F-COG-05 | 输入为黑板世界状态摘要（电池/是否看见人或方块/当前心情意图/关键事件）+ 可选摄像头快照 | M |
| F-COG-06 | 输出结构化 JSON（function calling），如 `{"intention":"search_person","mood":"anxious"}` | M |
| F-COG-07 | 工具接口草案：`set_intention`、`set_mood`、`play_animation`、`get_world_state`；工具只改目标/心情，由任务层实际执行 | M |
| F-COG-08 | **反射兜底（必须）**：确定性规则在模型未返回/超时/不可达时给默认意图与心情（看见人→follow；人丢→T1 疑惑/T2 焦急；低电量→停） | M |
| F-COG-09 | 模型返回可覆盖规则兜底，但**安全反射不可被覆盖** | M |
| F-COG-10 | （可选）低频抓一张摄像头快照让模型理解场景/认人辅助决策，不进实时环 | C |
| F-COG-11 | 本阶段**不做 TTS**；Gemma 仅输出文本 | W |

## 10. 安全反射需求

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| F-SAFE-01 | 悬崖检测触发时，立即停止并后退，在感知层就地闭环 | M |
| F-SAFE-02 | 碰撞（加速度突变）触发时立即停 | M |
| F-SAFE-03 | 安全反射不等待任务层/认知层，且不可被上层意图覆盖 | M |
| F-SAFE-04 | 低电量时进入停止/保护策略 | S |

## 11. 非功能需求

| 类别 | 需求 |
| --- | --- |
| **实时性** | 感知 ~30Hz、任务 ~10Hz；安全反射延迟尽可能低，悬崖触发即停 |
| **健壮性** | pycozmo 不稳定，需具备**重连与异常恢复**；弱检测帧做平滑 |
| **资源占用** | Gemma 4 26B-A4B（4-bit）约占 18GB 内存，与 MediaPipe、pycozmo 同台共存；32GB 够用但需关注峰值与首字延迟，必要时降到 E4B |
| **可测试性** | HAL 可 mock；三层可分别单测；提供调试面板/日志观察黑板 |
| **可配置性** | 阈值（T1/T2）、网络、动画名、LLM 配置集中于 `config.yaml` |
| **可移植性 / 解耦** | HAL 隔离 pycozmo，便于替换底层或在无实体时仿真 |
| **离线性** | 默认本地模型，无需外网 |

## 12. 模块划分与目录结构

```
super-baby/
  app/
    perception/    # 摄像头接收、MediaPipe Pose、方块/传感器汇总 → 黑板
    task/          # FSM: free_roam, play_cube, follow, search + 行为原语
    cognition/     # LLM agent loop, 工具定义, 意图/心情决策 + 规则兜底
    world/         # 黑板 / Belief store（层间共享状态）
    hal/           # pycozmo 封装（表情/电机/声音/LED/方块/连接 的薄抽象）

    moods/         # 心情 → 动画/LED 的映射表

  config.yaml      # 阈值(T1/T2)、网络、动画名、LLM 配置
  main.py          # 三层启动与接线；--demo connect/roam/follow
  docs/
```

`hal/` 把上层与 pycozmo 隔离，便于 mock 测试。

| 里程碑 | 内容 | 验收 |
| --- | --- | --- |
| **M1 连接** | HAL + 播放自带动画 | `--demo connect` 播放动画、打印电量 |

## 14. 风险与未决项

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 单目测距不精确 | 跟随距离只能近似，靠尺寸区间控制，可能抖动 | 多帧平滑 + 尺寸区间 + 居中伺服 |
| 摄像头分辨率/帧率低 | MediaPipe Pose 在低质画面可能漏检 | 多帧确认与平滑、误丢失保护 |
| 本地模型资源占用 | 约 18GB 内存，与感知/pycozmo 共存 | 关注峰值与首字延迟，必要时降到 E4B |
| Gemma 4 较新（2026-04） | 本地工具链（Ollama/MLX）、多模态/JSON 约束成熟度待验 | M4 实测验证，provider 可切换 |
| pycozmo 稳定性 | 官方自述"不稳定、开发中" | 重连与异常恢复 |
| 具体自带动画名未定 | M1/各心情动画 `.bin` 名称待选 | 实现时从 pycozmo 资源选定并配置化 |

## 15. 验收标准

总体以"三步各自 demo 可独立运行"为准：

1. **步骤一（连接）**：`--demo connect` 后 Cozmo 数秒内播放可见动画，控制台打印连接成功与电池电压，退出能安全断开。
2. **步骤二（自由活动）**：Cozmo 自主随机移动且遇悬崖立即停；方块被拍/被移动时 1s 内切对应心情动画并改变方块 LED；三层独立周期运行、黑板实时更新可观察。
3. **步骤三（跟人走）**：人在前方移动时 Cozmo 转向保持朝向人、远近变化时有前进/后退；跟随中持续播放匹配心情动画；人离开 ~2s 出现疑惑、~5s 升级焦急，人回来播放开心动画并恢复跟随。
4. **认知层（M4）**：模型能下发意图/心情并被任务层执行；模型超时/不可达时由规则兜底维持运行，安全反射始终不被覆盖。

| 模块级验收要点 | 通过标准 |
| --- | --- |
| HAL | 连接、动画、电机、LED、方块、音频封装可用且可 mock |
| 感知层 | MediaPipe Pose 输出稳定的 person 字段；传感器/方块状态实时入黑板 |
| 任务层 | 四个 FSM（free_roam/play_cube/follow/search）状态转移正确 |
| 认知层 | 结构化 JSON 输出可靠；反射兜底生效 |
| 安全 | 悬崖/碰撞即停，不可被覆盖 |
